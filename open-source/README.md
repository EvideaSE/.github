# About Open Source

**New to GitHub, open source, or collaborative development? Welcome.**

You don't need to be a programmer to follow or contribute to a project developed in the open. Good questions, careful reading, constructive criticism, and expertise from different fields are just as valuable.

This document introduces how we work and what we're building here.

## What is GitHub?

GitHub is a platform where people develop, document, discuss, and improve projects together. It also keeps a history of changes, making it possible to see how something has developed, who changed it, and why.

A few useful terms:

- **Organization:** A shared home for people and projects. Ours is [EvideaSE](https://github.com/EvideaSE).
- **Repository:** A project containing files and their revision history.
- **Commit:** A recorded change, usually accompanied by a short explanation.
- **Issue:** A place to ask questions, discuss ideas, or report problems.
- **Pull request:** A proposed change that others can examine and discuss before it becomes part of the project.
- **Review:** The process of checking, questioning, and improving proposed changes.

## What have we built so far?

We have created a GitHub organization and two public website repositories:

| Repository | Website |
|---|---|
| [Evidea Website](https://github.com/EvideaSE/Evidea-Website) | [evidea.se](https://evidea.se) |
| [Data Evidea Website](https://github.com/EvideaSE/Data-Evidea-Website) | [data.evidea.se](https://data.evidea.se) |

Both websites are published using **GitHub Pages**, a service that turns files in a repository into a public website.

We have also connected our own domain names through DNS, configured the repositories' `CNAME` files, and set up HTTPS.

The websites are published from their respective `main` branches. Changes to those branches can trigger new website deployments.

This gives us a simple foundation: the websites and their development history can be explored in one place.

## How can you participate?

You can start by exploring a repository and reading its files.

If something seems unclear, incomplete, or incorrect, asking a question can be a valuable first contribution.

As contribution processes are established, a typical collaboration might look like this:

1. Someone identifies an issue or suggests an improvement.
2. A change is proposed through a pull request.
3. Other people examine, discuss, and review it.
4. The change is improved and, if accepted, merged into the project.

This process creates a visible history of decisions and gives different perspectives an opportunity to improve the result.

## Open source and peer review

Open source is about more than publishing code. It involves making work available under licences that allow others to use, study, modify, and share it.

**A public GitHub repository is not automatically open source.** Each repository needs an appropriate licence to define how its contents may be reused.

Review is equally important. In software development, code review examines proposed technical changes. In research, scientific peer review evaluates methods, reasoning, evidence, and conclusions.

These are different processes, but both benefit from transparency, criticism, and the willingness to revise earlier decisions.

A review on GitHub does not, by itself, constitute scientific peer review.

## Where do we go from here?

This is just the beginning.

As Evidea develops, we'll expand our documentation, define contribution guidelines, and make it easier for people with different backgrounds to participate.

The aim is not simply to make our work visible, but to make it understandable, traceable, and open to constructive scrutiny.

**Curiosity is a perfectly good place to start.**
